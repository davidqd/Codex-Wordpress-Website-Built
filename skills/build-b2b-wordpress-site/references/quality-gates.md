# B2B WordPress 质量门禁

## 目录

1. 设计门禁
2. 原生可视化组件门禁
3. 内容门禁
4. 技术门禁
5. SEO/GEO 门禁
6. 转化门禁
7. 发布门禁
8. 交付证据

## 1. 设计门禁

- [ ] 已分析参考站或已建立明确风格方向
- [ ] 参考站和当前草稿已在相同的 1440px、390px 视口对比
- [ ] 已明确页面全宽/盒装框架、Header 层数和 Hero 模型
- [ ] 已输出设计 Token
- [ ] 已输出页面线框图
- [ ] 已建立可复用组件
- [ ] 主题 Pattern、Theme Options、Slider、Header/Footer 能力已盘点
- [ ] 没有用大量内联 HTML/CSS 重造主题已有组件
- [ ] 深浅区块节奏合理
- [ ] 没有重复 Hero、Proof 或 CTA
- [ ] 首屏轮廓、视觉焦点和信息密度符合已锁定的参考方向
- [ ] Hero 图片尺寸、构图和移动端裁切适合所选布局
- [ ] 首页已作为母版单独验收

## 2. 原生可视化组件门禁

- [ ] 首次主题版本已在后台逐个查看 Patterns、区块样式、Slider、Header/Footer Layout 和 Theme Options，或当前主题与已验证组件目录的 slug、版本、依赖和校验状态完全匹配
- [ ] 已输出主题组件能力对照表，包含来源、可编辑字段、采用情况和弃用原因
- [ ] 首次主题采集已先实际验证 MCP 能否返回 Pattern 名称、slug 和原始 Gutenberg 内容
- [ ] 已记录 MCP 候选工具、返回字段、权限状态以及成功结果或失败原因
- [ ] 只有 MCP 能力不存在、权限失败或内容不完整时才使用浏览器采集
- [ ] 已记录 Pattern 获取路径：MCP 直读、有效组件目录或首次浏览器 Pattern Lab 采集
- [ ] 同一主题版本的后续页面已优先通过 MCP 组合，没有重复使用浏览器逐页插入相同 Pattern
- [ ] 正式页面由 Gutenberg Blocks、主题 Patterns、主题 Slider 或主题原生组件组成
- [ ] 每个主要模块可在编辑器中独立选中、移动、复制、删除和修改
- [ ] 没有单个 Custom HTML、Classic Block、Shortcode 容器或代码块承载完整页面或主要区段
- [ ] 页面内容中没有 `<style>`，没有用页面级内联 CSS 完成正式页面
- [ ] 公共样式位于子主题或 Theme Additional CSS 等统一入口
- [ ] 自定义 HTML 仅用于无法由原生组件实现的小型局部元素，并记录了原因
- [ ] 产品分类、应用、质量流程、FAQ、RFQ 已保存为可复用 Pattern
- [ ] 已记录每个 Pattern 的名称、ID、同步状态和使用页面
- [ ] RFQ 使用真实表单组件，并记录表单 ID
- [ ] 已同时完成前台视觉和后台编辑体验验收
- [ ] MCP 已回读并验证顶级 Pattern 数量、H1、表单 ID、Classic/HTML/style 和演示内容

任何一项未通过，不得生成或保留以整页 HTML/CSS 代替原生组件的 WordPress 页面；只能输出文本线框、组件规划或站外视觉稿，更不得替换正式页面。

## 3. 内容门禁

- [ ] 前台语言符合要求
- [ ] 没有虚构数字、认证、客户或评价
- [ ] 占位符有明确标记
- [ ] 每个页面有清晰目标和下一步
- [ ] 产品描述没有把示例参数当真实参数

## 4. 技术门禁

- [ ] 页面 URL 和层级正确
- [ ] 每页只有一个 H1
- [ ] H2/H3 层级合理
- [ ] 图片有宽高、ALT 和合适格式
- [ ] 1440px 无异常
- [ ] 1024px 无异常
- [ ] 768px 无异常
- [ ] 390px 无横向溢出
- [ ] 表格在移动端可访问
- [ ] 所有核心链接有效
- [ ] 表单前端显示正常
- [ ] Header/Footer 不含演示标语、开发邮箱、默认 Logo 或无效社媒链接

## 5. SEO/GEO 门禁

- [ ] SEO Title 和 Meta Description 已设置或明确待设置
- [ ] canonical 正确
- [ ] 正式页面允许索引
- [ ] 草稿/参考页未公开
- [ ] 内链连接产品、分类、应用、质量、生产和联系页
- [ ] Schema 类型符合页面内容
- [ ] Blog 不存在空文章卡片和虚假作者

## 6. 转化门禁

- [ ] 首屏有明确 CTA
- [ ] 核心页面有询盘入口
- [ ] 页面底部没有重复 CTA
- [ ] 表单字段不过多
- [ ] 手机按钮至少约 48px 高
- [ ] Header/Footer 有联系入口

## 7. 发布门禁

只有以下全部满足才发布：

- [ ] 首页视觉验收通过
- [ ] 参考站重设计已保存桌面端和移动端同视口对比证据
- [ ] 正式首页不是在未经草稿验收的情况下直接覆盖
- [ ] 内页使用同一设计系统
- [ ] 浏览器实际检查完成
- [ ] MCP/后台状态与前端一致
- [ ] 没有阻止正式站点索引
- [ ] 用户要求的表单和 CTA 已确认
- [ ] 原生可视化组件门禁全部通过
- [ ] 页面模块实现清单和 Pattern ID 完整
- [ ] 剩余风险已明确

任何未通过项都必须保持 Draft、Private 或明确标记未完成。

## 8. 交付证据

最终报告至少包含：

- 实际修改的页面 ID 和 URL
- 发布状态
- H1 数量
- 区块数量
- 表单 ID
- 内链检查结果
- 检查过的视口宽度
- 采用的主题 Pattern、Theme Options 或自定义实现及其原因
- Pattern 获取路径、主题 slug/版本、组件目录校验状态和 MCP/浏览器职责分工
- MCP 采集预检使用的工具、返回字段、权限状态和回退原因
- 每个主要模块使用的 Pattern、Gutenberg Block、Slider、表单组件或自定义补充
- Pattern 名称、ID、同步状态和使用页面
- 后台区块列表与主要模块可编辑性检查结果
- 页面级 `<style>`、整页 Custom HTML 和 Classic Block 检查结果
- 有参考站时，参考站与当前站 1440px、390px 对比结果
- Header/Footer 演示信息清理结果
- 未验证项目和原因

不要只写“已优化”“响应式正常”或“结构与参考站一致”而不提供视觉检查证据。
