## 1. 设计输入

开始前收集：

- 行业、主营产品、目标市场和客户类型
- 品牌 Logo、已有色彩、字体和真实图片
- 参考网站与喜欢/不喜欢的部分
- 主题 Patterns、Theme Options 和模板限制
- 真实工厂、质量、证书和案例证据

没有品牌规范时，为工业 B2B 默认选择高可信、低装饰的方向，不使用过多渐变、玻璃效果或炫技动画。

参考站重设计必须先记录视觉骨架，不得只记录模块顺序：

- 页面框架：全宽、盒装或混合
- Header：单层或多层、Logo 位置、顶部信息条、导航高度
- Hero：全宽背景、Slider、视频、左右分栏或卡片式
- 首屏占比：Header 与 Hero 在 1440px、390px 下的可见高度
- 视觉焦点：标题、产品、工厂场景或 CTA
- 内容密度：首屏文字行数、按钮数量和辅助标签数量
- 图片策略：横向大场景、产品近景、裁切位置和遮罩

## 2. Token 合同

在页面制作前明确一张 Token 表：

| Token | 默认范围 | 说明 |
|---|---:|---|
| 内容宽度 | 1160–1280px | 全站只选一个主宽度 |
| 区块间距 | 48–80px | 用户有明确要求时优先 |
| 卡片间距 | 20–28px | 桌面端 |
| 卡片内边距 | 24–32px | 保持一致 |
| 正文宽度 | 680–820px | 居中说明文字 |
| 按钮高度 | 至少 46px | 移动端至少 48px |
| Hero 高度 | 560–760px | 首页 |
| 内页 Hero | 320–480px | 避免压过正文 |

常用工业配色：

- 深海军蓝：`#131E4A`
- 工业橙：`#FD5F17`
- 浅灰背景：`#F5F6F8`
- 正文：`#303747`
- 次级正文：`#64748B`
- 白色：`#FFFFFF`

配色应服从现有品牌；不能仅因为行业相同而强行覆盖品牌色。

## 3. 视觉节奏

遵循以下节奏：

1. 首屏大图建立行业与产品认知。
2. 浅色 Proof 卡片快速建立可信度。
3. 图文区解释公司与流程。
4. 深色区承载优势、流程或应用导航。
5. 白色产品卡片让访客恢复阅读节奏。
6. 深浅交替，避免连续多个同色卡片区。
7. 询盘表单靠近高意向内容，不在页面末尾重复同类 CTA。

区块之间需要“变化”，但组件内部需要“一致”。

## 4. 组件规则

### Hero

- 一个 H1。
- 价值主张不超过两行。
- 说明文字控制在 140–220 个英文字符。
- 一个主 CTA，一个次 CTA。
- 背景图增加遮罩，保证 WCAG AA 对比度。
- 先选择并锁定 Hero 模型。参考站是全宽背景图时，不得未经说明改成盒装左右分栏。
- 全宽 Hero 优先使用适合横向裁切的高分辨率场景图；产品近景应确认主体在桌面和移动端均不会被裁掉。
- 首屏必须形成一个明确视觉焦点，不能同时竞争 Logo、长标题、产品标签、浮层卡片和多个同级 CTA。

### Section Heading

- H2 与说明文字形成固定组合。
- 同级标题字号和间距一致。
- 用户要求居中时，所有页面统一执行，不在单个区块例外。

### Cards

- 同组卡片高度、边框、内边距一致。
- 每张卡片只表达一个重点。
- 不用未经确认的数字撑满 Proof 卡片。
- 3 张卡片优先三列，4 张卡片优先四列；窄屏自动换行。

### Image + Text

- 图片与文字比例通常为 50/50 或 45/55。
- 连续图文区应交替图片位置。
- 每张图片有真实 ALT，不堆砌关键词。

### CTA

- 同一视口附近不出现两个功能相同的 CTA Block。
- CTA 文案使用动作和结果：Get A Quote、Send Inquiry、Request a Sample。
- 主按钮只使用一种强调色。

### Form

- 放入白色或高对比卡片。
- 字段数量与询盘阶段匹配。
- 必填项最小化，但保留产品、数量、国家和规格说明。

## 5. 响应式规则

必须检查：

- 1440px：内容不能过宽，卡片不能稀疏。
- 1024px：四列可降为两列。
- 768px：图文区可变为单列，图片与文字顺序合理。
- 390px：H1 不溢出，按钮可点击，表格可横向滚动。

移动端禁止：

- 固定宽度大于视口
- 依赖 hover 才能访问内容
- 小于 44px 的关键点击目标
- 过大的 60px+ H1
- 图片使用固定高度导致严重裁切

## 6. 常见失败模式

- 从模块清单直接生成页面，没有线框图。
- 只分析参考站有哪些模块，没有分析全宽/盒装、Hero 类型和首屏轮廓。
- 参考站尚未完成同视口截图，就开始修改正式首页。
- 每个区块单独决定颜色和间距。
- 为追求“丰富”重复 Hero、Proof 和 CTA。
- 大量内联样式导致页面之间漂移。
- 用页面级 HTML 重造主题已有的 Slider、Header、Pattern 或联系组件。
- 用小尺寸产品近景替代参考站的大场景 Hero，却仍宣称视觉体验一致。
- 只修复横向溢出和列宽，就把“排版不乱”误判为“视觉通过”。
- 用占位数字、虚构认证或客户 Logo 填空。
- 只检查 HTML，不看真实桌面和手机呈现。
- 首页未定稿就批量复制到内页。
